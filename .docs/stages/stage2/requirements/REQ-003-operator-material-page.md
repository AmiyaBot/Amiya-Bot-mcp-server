## 背景与目标

- 原插件 AmiyaBot/Amiya-Bot-plugins 的 `operatorArchives` 插件支持指令 `/兔兔查询 [干员名] 材料`，输出 `operatorCost.html` 图片卡片；本项目尚未复刻该能力。
- 原插件材料页面内容为三大区块：
  1. 精英化材料（精英一 / 精英二，按阶段分组）；
  2. 技能通用升级材料（Lv2–7，全技能共用，按等级分组）；
  3. 技能专精材料（Lv8–10，按技能分列，专精一 / 二 / 三）。
  - 材料以图标 + 数量角标展示，卡片背景使用干员皮肤模糊图；1–2 星干员直接回复「博士，干员xxx不需要消耗材料进行升级哦~」。
- 本项目数据层已经解析好材料成本数据（`OperatorInfo.evolve_cost`、`SkillLevel.costs`，含 Lv2–7 通用与 Lv8–10 专精），但展示链路（模板 / 查询服务 / CLI 命令 / MCP 工具）完全缺失。
- 材料名称与图标需要关联 `item_table`（`resources/gamedata/excel/item_table.json`）与物品图标资源（`resources/assets/item/`，均已就位）。
- 本需求目标：复刻材料页面，输出图片卡片 + 结构化数据两种形态，并同时打通 CLI 与 MCP 两个通道。

## 待确认问题

### 1. 材料结构契约字段设计 — 方案已拟定（待用户确认）

对齐 STAGE2-RQ-002 语义化风格（中文键、嵌套、`_compact_value` 清洗空值），顶层 payload：

```json
{
  "名称": {"干员id": "char_172_svrash", "中文名": "银灰", "英文名": "SilverAsh", "星级": 6},
  "精英化材料": [
    {"阶段": "精英一", "材料": [{"名称": "酯原料", "数量": 5, "图标": "3221"}]},
    {"阶段": "精英二", "材料": [{"名称": "聚合剂", "数量": 4, "图标": "3223"}]}
  ],
  "技能升级材料": {
    "通用升级": [{"等级": 2, "材料": [{"名称": "...", "数量": 3, "图标": "..."}]}],
    "专精": [{"技能名": "强力击·γ型", "专精一": [...], "专精二": [...], "专精三": [...]}]
  }
}
```

要点：
- 材料条目统一为 `{"名称", "数量", "图标"}`；「图标」存 iconId 语义标识，不放 URL（图片形态由模板 data URI 承载，结构化形态不携带图片 URL，与 RQ-002 payload 不带 image_url 一致）。
- 精英化用数组 + 「阶段」字段（精英一 / 精英二），专精用数组 + 中文键，均不沿用原插件 dict 键遍历写法，适配 Jinja2。
- 精英化阶段 0（精零）无 evolveCost，不产出条目。
- 龙门币（GOLD 类型成本）不特殊处理：经 item_table 关联（id 4001，iconId GOLD）后与普通材料同构展示。
- 1–2 星干员不产出 payload，直接返回 message（对齐原插件）。

### 2. 材料图标路径映射规则 — 方案已拟定（Search-First 已完成）

- 数据源：`item_table` 已在 bundle 装载清单（`bundle.tables["gamedata"]["item_table"]`），取 `items[<id>].name`（名称）与 `.iconId`（图标标识），跳过 `p_char` 前缀（对齐原插件 `init_materials`）。
- 图标文件映射：`resources/assets/item/<iconId>.png`，文件名大小写与 iconId 一致（已验证 `EXP_PLAYER.png` 等样本）；技能图标同规则 `resources/assets/skill/<iconId>.png`。
- 注入机制：沿用现有 `build_skill_icon_data` 模式（`src/domain/services/operator.py`）——读文件转 base64 data URI 注入 payload，无后缀自动补 `.png`，文件缺失则跳过该图标（降级为名称文本展示）。
- 精英化 / 专精徽标图标（原插件 `level/evolve1.png`、`evolve2.png`、`master1~3.png`）：复制到 `data/templates/operator_material/assets/`（对齐 `operator_info/assets/` 现有做法），模板内引用。

### 3. MCP 工具返回契约细节 — 方案已拟定（待用户确认）

- `get_operator_material(operator_id)` 原样返回 `QueryExecutionResult.to_response()`，同时携带 `data`（材料 payload）与 `image_url`（及本地场景下的 `image_path`），不剥离字段。
- 理由：材料页面的图片与结构化数据都是主输出，且 `to_response` 只含非 None 字段，天然兼容 1–2 星干员「只有 message 没有图片」场景。
- CLI 侧对齐 RQ-002 模式：`material <干员名>` 默认输出 Markdown 材料清单（附图片引用），`--json` 输出完整 response。

### 4. 卡片视觉规范 — 已确认（2026-08-13）

按原插件风格：皮肤模糊背景 + 三大区块布局 + 材料图标带数量角标；视口沿用原插件 1280×720。
