# 提交执行规范

## 授权边界

- 用户明确要求“提交”时，只创建本地提交，使用 `--no-push`。
- 只有用户同时明确要求“推送”时，才允许把提交推送到当前分支的 upstream。
- 发布、打 tag、创建 PR、修改代码或运行检查的授权都不等于提交或推送授权。
- 一旦用户明确要求提交，授权范围就是当前工作区的全部已跟踪、未跟踪、已暂存和未暂存改动，不区分改动由用户、其他 Agent、既有工作还是当前任务产生。

## 提交前审计

在项目根目录分别运行以下只读命令：

```bash
git status --short --branch
git diff --stat
git diff --cached --stat
git diff --check
```

读取全部修改、删除、暂存和未跟踪文件的概要，用于生成能够覆盖整个工作区的提交信息。`commit-all.sh` 会通过 `git add -A` 暂存根仓库的全部非忽略改动，这是本 skill 的有意行为。

不得套用“只提交当前 Agent 的改动”或“保留用户已有改动”的默认策略。来源不明、用户自己的、其他 Agent 产生的或与当前任务无关的普通改动，都不得成为停止、排除文件或缩小提交范围的理由。

不得提交 `.env`、凭据、令牌、私钥、运行时资源、缓存、日志或其他敏感/生成文件。发现疑似敏感文件时停止并向用户说明。

## 提交信息

查看近期历史以匹配仓库风格：

```bash
git log -20 --pretty=format:%s
```

提交信息使用简洁的 Conventional Commits 格式，建议不超过 72 个字符：

- `feat:`：新增或扩展用户可用能力。
- `fix:`：修复用户可观察到的错误。
- `docs:`：仅修改文档。
- `test:`：仅修改测试或测试设施。
- `chore:`：发布、依赖、CI、构建和其他维护工作。
- `refactor:`：不改变外部行为的代码重构。

默认沿用近期提交使用的英文摘要；用户指定中文或现有改动上下文以中文为主时可以使用中文。涉及干员、技能、材料、关卡、敌人或集成战略藏品等游戏实体时，优先复用当前源码、测试、README 或用户输入中的既有名称；没有可靠中文名称时保留资源 ID 或英文标识，不自行翻译。

`fix:` 优先描述用户看到的错误表现，不用内部实现细节代替问题本身。如果工作区包含多项独立改动，提交信息必须概括全部改动；不得只描述当前 Agent 完成的部分，也不得因此擅自拆分提交。

## 执行

仅创建本地提交：

```bash
./commit-all.sh --no-push "<提交信息>"
```

用户明确授权提交并推送：

```bash
./commit-all.sh "<提交信息>"
```

禁止直接执行 `git commit`，也禁止任何绕过项目脚本的提交方式。

## 执行后验证

运行 `git status --short --branch` 和 `git log -1 --oneline`，核对提交结果。最终报告提交哈希、提交信息、是否已推送，以及任何未提交或未推送状态。脚本推送失败时不得自动 pull、merge、rebase 或重试；保留本地提交并报告错误。
